Perfeito — isso confirma que o registro JDBC de eventos do Spring Modulith está funcionando corretamente.
O fluxo ocorrido foi:

OrderService.createOrder()
  → publica OrderCreatedEvent
  → Spring Modulith grava EVENT_PUBLICATION
  → InventoryOrderCreatedListener recebe o evento
  → InventoryService.reserveItems() é executado
  → publicação é marcada como COMPLETED

Interpretação dos campos:
•
id: identificador da publicação, não do pedido.
•
listener_id: método que recebeu o evento.
•
event_type: classe pública do evento.
•
serialized_event: evento completo serializado em JSON.
•
publication_date: momento em que a publicação foi registrada.
•
completion_date: momento em que o listener terminou.
•
status = COMPLETED: o listener terminou sem lançar exceção.
•
completion_attempts = 1: foi processado na primeira tentativa.
O createdAt aparece como 21:51 UTC, enquanto o banco mostra 18:51 -03:00.
São exatamente o mesmo instante, apenas em fusos horários diferentes.
Uma observação importante: atualmente, InventoryService.reserveItems()
somente registra uma mensagem no log:

LOGGER.info(
        "Reservando {} item(ns) do estoque para o pedido {}",
        items.size(),
        orderId
);

Sugiro uma arquitetura hexagonal pragmática: domínio puro, aplicação definida por portas e tecnologias concentradas em adaptadores.

com/market/order
├── OrderCreatedEvent.java                  # API pública do módulo
├── package-info.java
└── internal
    ├── domain
    │   ├── model
    │   │   ├── Order.java
    │   │   └── OrderItem.java
    │   ├── exception
    │   │   └── OrderDomainException.java
    │   └── package-info.java
    │
    ├── application
    │   ├── port
    │   │   ├── in
    │   │   │   ├── CreateOrderUseCase.java
    │   │   │   ├── CreateOrderCommand.java
    │   │   │   └── CreateOrderResult.java
    │   │   └── out
    │   │       ├── OrderRepository.java
    │   │       └── OrderEventPublisher.java
    │   ├── service
    │   │   └── CreateOrderService.java
    │   └── package-info.java
    │
    └── adapter
        ├── in
        │   └── web
        │       ├── CreateOrderRequest.java
        │       ├── OrderController.java
        │       └── OrderHttpApi.java
        │
        └── out
            ├── persistence
            │   └── jdbc
            │       ├── OrderPersistenceAdapter.java
            │       ├── SpringDataOrderRepository.java
            │       ├── OrderJdbcEntity.java
            │       ├── OrderItemJdbcEntity.java
            │       └── OrderPersistenceMapper.java
            │
            └── event
                └── SpringOrderEventPublisher.java



A direção das dependências será:

OrderController
    → CreateOrderUseCase
        ← CreateOrderService
            → domínio
            → OrderRepository
            → OrderEventPublisher

OrderPersistenceAdapter
    → implementa OrderRepository

SpringOrderEventPublisher
    → implementa OrderEventPublisher
